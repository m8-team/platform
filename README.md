# M8 Platform

Монорепозиторий платформы: backend на Go, будущая веб-консоль, API-контракты и инфраструктура. Основные модули: Resource Manager, Identity, Authentication, Access.

Сейчас репозиторий содержит только структуру, инженерные правила и шаблоны процесса Spec-Driven Development (SDD). Реализаций, API-методов, миграций и инфраструктурных ресурсов пока нет. Каталоги с `.gitkeep` резервируют место для будущей работы.

## Начало работы

Прочитайте [принципы](docs/principles.md), [обзор архитектуры](docs/architecture/overview.md), [границы модулей](docs/architecture/module-boundaries.md) и [цикл SDD](docs/development/sdd-workflow.md). Навигация по материалам — в [документации](docs/README.md), правила работы ИИ — в [AGENTS.md](AGENTS.md).

Для первой функции уточните требования и открытые решения модуля, затем создайте `docs/specs/<module>/<feature>/spec.md` по [шаблону](docs/specs/_templates/spec.md). План и задачи добавляйте по сложности изменения; для небольшой задачи достаточно issue. Подробнее — в [каталоге спецификаций](docs/specs/README.md).

## Документация Diplodoc

Из корня репозитория: `npm --prefix docs ci`, затем `npm --prefix docs run build`. Для локального просмотра: `npm --prefix docs run preview` (нужен Python 3), адрес — http://localhost:8000. Сборка требует Node.js 24.21.0+ и npm 11.19.0+.

Весь toolchain документации находится в `docs/`: настройки — `docs/.yfm`, навигация — `docs/toc.yaml`, npm-окружение — `docs/package.json`, результат — `docs/build/site/`. Подробнее: [ведение и сборка документации](docs/development/diplodoc.md).

## Отложенные решения

`go.mod` отсутствует намеренно: его создание отложено до выбора Go module path и версии Go. `go.sum` не создаётся вручную. Зависимости приложения и SDD-инструменты на этапе каркаса не устанавливаются; команд сборки и запуска приложения пока нет. Для документации установлен отдельный инструмент сборки Diplodoc.

Перед реализацией первой функции следует определить применимые к ней границы модулей, модель арендатора, контракты и взаимодействия, хранение и транзакционные границы, способ проверки и поставки. Стек веб-консоли, топология развёртывания и инфраструктурные технологии остаются открытыми до появления соответствующих требований. Наличие каталогов не означает принятия этих решений.
