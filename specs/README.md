# Спецификации

Одна спецификация описывает законченную возможность системы. Путь функции — `specs/<module>/<feature>/`.

- `spec.md` — поведение, требования и сценарии приёмки.
- `plan.md` — технический способ реализации, по сложности изменения.
- `tasks.md` — шаги реализации и проверки, по сложности изменения.
- `specs/<module>/module.md` — ответственность и общие инварианты модуля.

Для небольшой задачи достаточно issue. Новая возможность получает спецификацию; редакционные правки и простые исправления не требуют полного набора документов. Общий порядок определён в [цикле SDD](../docs/development/sdd-workflow.md).

## Модули

- [Resource Manager](resource-manager/module.md).
- [Identity](identity/module.md).
- [Authentication](authentication/module.md).
- [Access](access/module.md).

Границы модулей — исходное предложение; подтверждённых спецификаций функций пока нет. Если возможность затрагивает несколько модулей, выберите основной по ответственности и укажите остальных в одной спецификации. Не копируйте требования между модулями; неясное владение оставьте открытым вопросом до согласования.

## Шаблоны

Копируйте только необходимые шаблоны. Замените placeholders и пересчитайте относительные ссылки. Разделы «по ситуации» заполняются при применимости. Шаблоны не содержат утверждённых требований и результатов проверок.

Общие правила берутся из [принципов](../docs/principles.md), [глоссария](../docs/glossary.md), [правил документации](../docs/development/documentation-rules.md) и [версионирования](../docs/development/versioning.md). Контракты хранятся только в [api/proto/](../api/proto/); спецификации содержат ссылки на них. Приоритеты, сроки и ответственные остаются в трекере.
