# Документация в Diplodoc

Документация M8 Platform оформляется в Yandex Flavored Markdown (YFM) и собирается [Diplodoc](https://diplodoc.com/docs/ru/). Сайт объединяет архитектуру, процесс разработки, спецификации модулей, шаблоны и инструкции для ИИ.

## Единый источник

Редактируйте исходные документы в `docs/`, корневых `README.md` и `AGENTS.md`. Их размещение и история SDD сохраняются. Не создавайте вручную вторую копию спецификаций для сайта.

Корневой [toc.yaml](../../toc.yaml) задаёт навигацию, [.yfm](../../.yfm) — параметры Diplodoc. Главная страница сайта генерируется из корневого `README.md`. Конфигурация включает русский интерфейс, локальный поиск и HTML-содержимое страниц.

## Сборка и просмотр

Нужны Node.js 24+ и npm 11.5.1+. Команды выполняются из корня репозитория:

```bash
npm ci
npm run docs:build
```

Результат — `build/docs/`. Версия Diplodoc закреплена в `package.json`, транзитивные зависимости — в `package-lock.json`.

Для локального просмотра требуется Python 3:

```bash
npm run docs:preview
```

Откройте [localhost:8000](http://localhost:8000). Сервер доступен только на локальной машине. После изменения исходников повторите сборку. Открытие HTML напрямую через `file://` не заменяет просмотр через HTTP, необходимый для полноценной работы поиска и ресурсов.

## Как устроена сборка

[scripts/prepare-docs.mjs](../../scripts/prepare-docs.mjs) готовит временный каталог `build/docs-input/`, сохраняя структуру `docs/`, включая `docs/specs/`. Затем Diplodoc создаёт сайт в `build/docs/`. Оба каталога пересоздаются при сборке и исключены из Git правилом `/build/`.

Относительные ссылки между страницами остаются внутренними. Ссылки на код, исходные API-контракты, конфигурацию и установленные skills в сборке преобразуются в ссылки GitHub. Исходные Markdown-файлы при этом не меняются. Сами skills и код не включаются в сайт документации.

По умолчанию ссылки на исходники указывают на ветку `new`. Для сборки конкретной ревизии задайте `DOCS_SOURCE_REF` равным commit SHA. CI задаёт его автоматически. Несуществующая цель относительной Markdown-ссылки останавливает подготовку; предупреждения Diplodoc останавливают строгую сборку.

## Добавление страницы

1. Создайте документ в соответствующем разделе `docs/`; SDD-артефакты размещайте в `docs/specs/` согласно [правилам документации](documentation-rules.md).
2. Добавьте страницу в корневой `toc.yaml`; путь указывается от корня подготовленной документации, например `docs/specs/resource-manager/create-organization/spec.md`.
3. Используйте относительные ссылки на `.md` и существующие ресурсы. Названия будущих путей записывайте как inline code. Для ссылок с пробелами используйте URL-кодирование.
4. Запустите `npm run docs:build` и проверьте новую страницу, меню и переходы через локальный HTTP-сервер.

Фрагменты для YFM include и изображения храните рядом с документацией. Их не нужно добавлять в меню как самостоятельные страницы. Не используйте корневые URL вида `/docs/...`: они мешают размещению сайта под префиксом.

## CI и публикация

Workflow [documentation.yml](../../.github/workflows/documentation.yml) выполняет `npm ci` и сборку при изменениях документации и её инструментов. Готовый сайт сохраняется как artifact `diplodoc-site` на 7 дней.

Сборка не публикует сайт. Хостинг, адрес и доступ выбираются отдельно; наличие CI artifact не означает публичную публикацию документации.
