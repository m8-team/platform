# Версионирование

## Документы и спецификации

Актуальная спецификация хранится в одном `spec.md`, история — в Git. Редакция документа определяется коммитом; файлы вида `spec-v2-final.md` не создаются. Стабильный идентификатор спецификации не является номером её редакции.

Версии спецификации, сервиса и API независимы: редакция требований не задаёт автоматически версию сервиса или API. Один релиз может включать несколько изменений спецификаций. Редакционная правка документа не требует релиза сервиса.

## Статусы спецификации

| Статус | Значение |
| --- | --- |
| Draft | Поведение обсуждается; открытые вопросы ещё могут препятствовать согласованию |
| Accepted | Согласованное целевое поведение; реализация не подразумевается |
| Implemented | Описанное поведение реализовано и проверено; есть подтверждающие ссылки |
| Deprecated | Поведение выводится из использования или более не применяется; описаны последствия и, если есть, замена |

Обычный путь — Draft → Accepted → Implemented → Deprecated. Переходы опираются на фактическое согласование или проверки, а не на завершение редактирования файла. Implemented не означает автоматически, что состоялся релиз: поставка фиксируется отдельно.

Если целевое поведение Accepted или Implemented существенно меняется, обновите тот же `spec.md`, явно опишите отличие от поставленного поведения и верните изменение на согласование в Draft. Затем используйте Accepted до реализации и проверок новой редакции. Для предыдущего поведения ссылайтесь на коммит или релиз; дубликат спецификации не создавайте.

## Сервисы и API

Правила нумерации релизов сервисов и состав релизной единицы предстоит выбрать при планировании поставки. Не выводите их из структуры `cmd/`.

Версии API сосуществуют при необходимости поддержки несовместимых контрактов. Введение новой версии требует описания совместимости, миграции потребителей и условий завершения поддержки прежней. Наличие пустого каталога `v1/` не означает выпущенную версию API.

## ADR

Существенный пересмотр принятого ADR оформляется новым ADR со ссылкой на предыдущий. Предыдущий документ сохраняет исторический контекст и получает ссылку на замену. Статусы и правила — в [реестре ADR](../adr/README.md).
