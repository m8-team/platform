# M8 Resource Manager v1 — OrgUnit gRPC delivery slice

Canonical protobuf package: `m8.platform.resourcemanager.v1`.

## Implemented in this PR

- Go bindings for `OrgUnit`, `OrgStructureService` and `OrgUnitChangeSetService`, generated by Buf.
- `OrgStructureServer` registered via the existing Fx gRPC registration group.
- `GetOrgUnit`, `ListOrgUnits`, `ListOrgUnitAncestors`, `ListOrgUnitDescendants`.
- `ValidateOrgUnitChangeSet` (read-only impact and structural validation) and `ApplyOrgUnitChangeSet` (immediate-only optimistic revision and idempotency).
- Authenticated `Actor` is read exclusively from a context value installed by *trusted* server authentication middleware; request body and gRPC metadata are **not** trusted as an actor.
- A deny-all authorization and impact gate by default, including all write operations; explicit `AllowUnauthenticated` development mode enables local testing. This is **not** a production Access adapter.
- HMAC-signed, revision-bound, actor-bound paging, with individual OrgUnit visibility checks before pagination.
- Deterministic gRPC errors for invalid input, missing objects, permission denials, stale revisions and unsatisfied preconditions.

## Important production blockers

1. The Fx module currently supplies `memory.OrgStructureStore` for test/dev only. It is **empty** until seeded by a trusted lifecycle flow; production must replace it with the YDB repository and wire actual Organization provisioning. The YDB store from P0.3 is not yet activated by this RPC module.
2. An authenticated server interceptor must insert `orgstructure.Actor` via `grpcadapter.WithOrgStructureActor`. Without it RPCs return `UNAUTHENTICATED`.
3. M8 Access must implement production org/unit read policies and mutation/impact checks before enabling writes.
4. `ListOrgUnitVersions` deliberately returns `UNIMPLEMENTED`: the bitemporal history writer/query is pending.
5. Idempotency requires `idempotency_key == change_set.id` in this initial RPC contract. The distinct identity/idempotency semantics should be designed before broad client adoption.
6. Validation is immediate-only: scheduled and retroactive 1C:ZUP updates need the temporal workflow.
7. Real YDB serializable transaction integration and crash recovery tests are pending. Do not deploy this as a durable control plane.
