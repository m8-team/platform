# Границы модулей

Ниже приведено исходное предложение, а не утверждённая предметная модель. Ответственность, инварианты и интеграции уточняются при работе над первой затрагивающей их функцией.

| Модуль | Предлагаемая ответственность | Описание |
| --- | --- | --- |
| Resource Manager | Организации, workspace и проекты, их жизненный цикл | [module.md](../../specs/resource-manager/module.md) |
| Identity | Идентичности и связанные профили | [module.md](../../specs/identity/module.md) |
| Authentication | Подтверждение личности, authentication challenges и процессы аутентификации | [module.md](../../specs/authentication/module.md) |
| Access | Роли, назначения, отношения доступа и проверка разрешений | [module.md](../../specs/access/module.md) |

## Имена в репозитории

| Модуль | Спецификации и точка запуска | Код | Контракты |
| --- | --- | --- | --- |
| Resource Manager | `resource-manager` | `internal/resource/` | `api/proto/m8/resources/v1/` |
| Identity | `identity` | `internal/identity/` | `api/proto/m8/identity/v1/` |
| Authentication | `authentication` | `internal/authentication/` | `api/proto/m8/authentication/v1/` |
| Access | `access` | `internal/access/` | `api/proto/m8/access/v1/` |

Различие имён `resource-manager`, `resource` и `resources` намеренно отражено в структуре. Каталог `api/proto/m8/events/v1/` зарезервирован для возможных контрактов событий; владельцы и состав событий не определены.

## Открытые решения об интеграциях

- Resource Manager ↔ Access: как ресурсы участвуют в проверке разрешений, как жизненный цикл влияет на доступ, где проверяется существование ресурса.
- Identity ↔ Authentication: как подтверждение личности связано с идентичностью; кто владеет учётными данными и сессиями, если они потребуются.
- Identity ↔ Access: какие субъекты поддерживаются, как изменения их состояния влияют на доступ.
- Authentication ↔ Access: какие сведения о подтверждённом субъекте передаются для авторизации и как устанавливается доверие.
- Для всех модулей: соответствие арендатора предметным сущностям, владение данными, способ взаимодействия, согласованность и поведение при недоступности зависимости.

Эти связи — вопросы для проработки, а не список обязательных вызовов, событий или API. Конкретные интеграции описываются в спецификации и плане нужной функции; значимые решения — в ADR.
