# ClickHouse Data Transfer v5 — безопасная обработка `ReplacingMergeTree` без версии

Подготовлено на основании пользовательского ClickHouse `26.8.33.10-yc.3` и DDL исходных БД. **Реальных подключений из этого окружения не выполнялось**. Скрипт выполняет прямую передачу между кластерами через `remoteSecure()`; `diagnose_replacing.py` выполняет только `SELECT`.

## Почему возникло расхождение

У `zendendb.ПланПродаж_ecom` исходный движок — `ReplacingMergeTree` **без аргумента версии**, ключ `ORDER BY (Подразделение, Дата)`. По журналу 492 исходные физические строки превратились в 430 строк `FINAL`; после копирования целевой `FINAL` также вернул 430 строк, но итоговые контрольные суммы различаются. Передача обычным `INSERT SELECT` может изменить порядок версий внутри/между частями. Это может менять строку-победителя у таблицы без параметра `ver`.

По экспорту DDL **130 из 150** исходных таблиц `ReplacingMergeTree` не имеют `ver`. Не все содержат дубликаты; новая защита определяется по живому `system.tables.engine_full` и сравнению физического `count()` с `count() FINAL`.

## Использование

1. Сделайте резервную копию локального `data_transfer_progress/progress.json`.
2. Замените только `transfer_data.py` файлом из архива, сохранив `config.json` и журнал. Для диагностики скопируйте рядом `diagnose_replacing.py`.
3. Диагностируйте текущую таблицу без записей:

```bash
python3 diagnose_replacing.py --config config.json \
  --table 'zendendb.ПланПродаж_ecom' \
  --report replacing_diff_report.json
```

Сравниваются `source FINAL`, `target FINAL`, физические версии обеих таблиц, вычисляются SHA-256 для каждой строки и выводятся отличающиеся ключи/колонки **без вывода самих значений колонок**. `DateTime` приводится к Unix seconds для корректного сравнения вне зависимости от настройки часового пояса. Отчёт записывается с правами `0600`, поскольку в нём есть идентификаторы ключей.

4. Чтобы продолжить миграцию **остальных** таблиц, не повторяя вставки в `UNCERTAIN`, используйте только при реально остановленных изменениях в источнике:

```bash
python3 transfer_data.py --config config.json --apply \
  --ack-source-frozen --resume \
  --skip-uncertain --skip-no-version-duplicates \
  --limit 20
```

Флаги:
- `--skip-uncertain` — оставляет `COPYING`, `VERIFYING`, `UNCERTAIN` нетронутыми и продолжает другие таблицы; применяется только с `--resume`.
- `--skip-no-version-duplicates` — если движок `ReplacingMergeTree` **без версии** и `count()` больше `count() FINAL`, запрещает копирование такой таблицы обычным `INSERT SELECT`, оставляет её для отдельного решения. Не помечает `DONE`.
- Флаг без `--skip-no-version-duplicates` останавливает миграцию при обнаружении такой таблицы до `INSERT`.
- `--limit` задаёт число кандидатных таблиц *до* отсева небезопасных, так что фактически скопированных таблиц может быть меньше.

В конце скрипт сообщает `INCOMPLETE`, если какие-либо таблицы пропущены; такое сообщение **не означает завершение общей миграции**.

## Что делать с `ПланПродаж_ecom`

До выяснения причины **не повторяйте `--apply` для неё**, не очищайте её и не меняйте `progress.json` вручную. Диагностика покажет, содержится ли победитель целевой таблицы среди физических строк источника. Если да, различие с большой вероятностью в порядке выбора версии. Если нет — необходимо разбирать возможную конвертацию значений (например, время/Decimal), изменение источника или иной дефект.

Варианты исправления после диагностики требуют осознанного выбора:
1. Сохранить **логическое состояние `FINAL`**: перенести отобранные строки `FINAL` в очищенную/новую целевую таблицу, после резервного копирования и контролируемого переключения; при этом физическая история версий будет потеряна.
2. Сохранить **физические строки и историю**, включая внутреннюю семантику «последней вставки»: нужно рассматривать part-preserving/backup-restore миграцию, а не обычный `INSERT SELECT`.
3. Поменять модель версионирования на `ReplacingMergeTree(timestamp)` — это **изменение семантики таблицы**, поэтому текущий мигратор не делает его автоматически.

`--reconcile` и `--mark-done` в `transfer_data.py` остаются и будут применимы только после фактического совпадения логических контрольных сумм.

## Безопасность

- Скрипт не подключён к вашим кластерам автоматически; реальную корректность запросов нужно проверить на них.
- `--ack-source-frozen` — заявление оператора, **не программная остановка загрузки**.
- `diagnose_replacing.py` читает 4 небольшие выборки для заданной таблицы; для других таблиц в этой версии предусмотрен запрет из соображений осторожности.
- Локальные тесты: `python3 -m unittest discover -v`.
